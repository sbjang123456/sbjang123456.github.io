2026년 9월 9일에 유니티 공식 블로그가 Claude Code용 공식 Unity 플러그인
출시를 알렸다. 글쓴이는 유니티의 AI 제품 디렉터 Rachel Zhao다. 유니티는 지난
Unite 서울에서 코딩 에이전트가 터미널에서 엔진을 다루게 하는 Unity CLI를
내놓았고, 이번 플러그인은 그 다음 단계다. 짧게 말하면 **유니티 엔지니어가 쓴
스킬 묶음과 Unity CLI, 에디터를 실시간으로 제어하는 MCP 서버를 한 번에
설치하는 자체 개발(first-party) 플러그인**이다. 이 글은 무엇이 나왔는지 훑어
두는 용도로 짧게 정리한다.

## 왜 만들었다고 하나

원문은 범용 코딩 에이전트를 유니티 프로젝트에 붙였을 때의 문제를 계약
개발자에 비유한다. 경험이 많고 빠르지만 이 코드베이스를 본 적이 없어서,
스프라이트 아틀라스를 동작은 하되 팀 방식과 다르게 짜거나 팀이 표준으로 정한
UI 프레임워크 대신 자기가 아는 것을 골라 버린다. 결과물이 그럴듯한 추측에
머무는 셈이다.

플러그인은 이 간극을 메우려고 에이전트에게 유니티가 실제로 일하는 방식을
가르친다. 프로젝트가 자산을 어디에 두는지, 아틀라스를 어떻게 만들어야 하는지,
URP 렌더러 기능이 돌아가려면 무엇을 먼저 만족해야 하는지가 그 예다. 유니티
개발자에게 새로운 일은 아니지만, 에이전트가 제3자 자료를 모아 답을 조립하는
대신 유니티가 준 답을 들고 접근한다는 점이 달라진다고 설명한다.

## 무엇이 들어 있나

플러그인 하나가 세 가지를 설치한다.

- **스킬 29개**: 유니티 각 기능을 담당하는 팀이 쓴 작업 절차다. 앞으로 더
  추가할 예정이라고 한다
- **Unity CLI**: 터미널에서 유니티를 구동한다. 에디터 설치, 라이선스, 빌드,
  로그까지 다룬다
- **MCP 서버**: 실행 중인 에디터를 실시간으로 제어한다. GameObject를 만들고
  고치고, 씬과 에셋을 편집하고, 계층 구조를 검사하고, C# 코드를 실행한다

명령 하나로 설치되고 프로젝트별 설정이나 컴퓨터를 옮길 때 복사할 파일이
없다는 점을 강조한다. 스킬은 아홉 갈래로 나뉜다.

| 분류 | 스킬 | 다루는 일 |
| :-- | :-- | :-- |
| 시작하기·도구 | `/new-unity-project`, `/unity-cli`, `/unity-package-management` | 새 프로젝트 안내 흐름, 터미널에서 에디터 구동, UPM 패키지 관리 |
| UI·텍스트 | `/ui`, `/ui-uitk`, `/ui-ugui`, `/ui-imgui`, `/optimize-text-mesh-pro` | 프로젝트가 쓰는 UI 시스템을 먼저 감지해 UI Toolkit, uGUI, IMGUI 전문 스킬로 넘김. TextMeshPro 최적화 |
| 2D·스프라이트 | `/2d-pixel-perfect`, `/sprite-editor`, `/sprite-segment-3x3grid`, `/manage-sprite-atlas`, `/tilemap-palette-create`, `/tilemap-ruletile-createempty`, `/tilemap-ruletile-createfromsegment` | 픽셀 퍼펙트 렌더링, 스프라이트 편집과 아틀라스, 타일 팔레트와 RuleTile 생성 |
| 그래픽·렌더링 | `/urp-postprocessing`, `/shader-graph-create-custom-node`, `/validate-urp-render-graph-renderer-feature` | URP 포스트 프로세싱, HLSL로 Shader Graph 커스텀 노드 생성, Render Graph 기반 렌더러 기능 검토 |
| 오디오 | `/audio-setup-mixers`, `/optimize-audio`, `/setup-vivox-voice-chat` | 오디오 소스를 믹서 그룹으로 분류, 메모리와 CPU 비용 절감, Vivox 음성 채팅 |
| 씬·게임플레이 | `/initialize-ai-navigation`, `/physics-3d-collision` | NavMesh 설정, 3D 물리 충돌 문제 진단 |
| 수익화·라이브 운영 | `/implement-in-app-purchases`, `/levelplay-unity-integration`, `/build-live-game` | Unity IAP, LevelPlay 광고 미디에이션, Unity Services 기반 라이브 서비스 기능 |
| 멀티플레이어 | `/setup-multiplayer-services` | Unity Multiplayer Services로 매치메이킹, 로비, 세션 기반 플레이 |
| 플랫폼·현지화 | `/optimize-web`, `/localization` | WebGL과 WebGPU 빌드 경량화, Unity Localization 설정 |

몇 가지 스킬은 설명이 눈에 띈다. `/ui`는 코드를 쓰기 전에 프로젝트의 UI
시스템을 감지하는 라우터 역할이고, `/ui-imgui`는 유지보수 전용이라고 못 박아
새 에디터 UI는 UI Toolkit을 기본으로 삼는다. `/audio-setup-mixers`는 분류하지
못한 소스를 조용히 건너뛰지 않고 보고한다고 적어 두었다.

## 왜 공식 플러그인인가

커뮤니티가 이미 유용한 플러그인을 많이 내놓았다는 점을 인정하면서도, 자체
개발 플러그인을 만든 이유를 세 가지로 든다. 해당 기능을 소유한 유니티 팀이
직접 쓴 스킬이고, 보안 검토를 거쳤고, 문서가 엔진과 발맞춰 갱신된다는
것이다. 스킬 없이 Claude에게 낯선 작업을 시키는 것과 비교하면 오류가 적고,
토큰을 덜 쓰고, 더 적은 턴에 작업을 끝낼 수 있다고 한다.

## 설치는 두 줄이다

플러그인은 Claude 파트너 플러그인 목록에 올라 있고, 터미널의 Claude Code나
Claude 데스크톱 앱 안의 Claude Code에서 설치한다. 유니티 공식 문서가 안내하는
명령은 다음과 같다.

```text
/plugin marketplace add Unity-Technologies/unity-agent-plugin
/plugin install unity@unity-agent-plugin
```

설치할 때 범위를 고른다. 여러 유니티 프로젝트를 다루면 사용자 범위, 팀 표준으로
삼으려면 저장소에 공유되는 프로젝트 범위, 이 저장소에서만 쓰려면 로컬 범위다.
설치가 끝나면 `/unity:`를 입력해 스킬 목록이 뜨는지 확인한다.

Claude Code는 이 플러그인을 설치할 수 있는 첫 코딩 에이전트고, 올해 안에
다른 코딩 에이전트에도 제공할 계획이라고 한다. 자세한 문서는
[docs.unity.com](https://docs.unity.com/en-us/ai/unity-plugin/claude-code)에
있다.

## 읽고 남는 것

유니티가 엔진 기능마다 스킬을 쓰고 CLI와 MCP 서버까지 묶어 배포하는 방식은,
프레임워크나 엔진 쪽이 에이전트를 자기 방식대로 길들이는 채널을 직접 쥐는
흐름으로 읽힌다. 스킬을 명령 하나로 설치하고 엔진 갱신에 따라 함께 갱신되는
구조라면, 프로젝트마다 CLAUDE.md에 유니티 관례를 적어 두던 일의 상당 부분이
플러그인으로 옮겨 갈 것이다. 유니티를 쓰지 않더라도 "공식 플러그인이 곧
공식 문서의 새로운 형태"가 되는 사례로 기억해 둘 만하다.
